# Evil Creatives

## Navbar logo color is luminance-driven and already correct
The navbar logo auto-switches black/white based on the luminance of the section under it (`onLight` detection). It computes correctly — e.g. on the hero it resolves to black.

**Why:** A user-reported "logo shows white on the hero" was a STALE canvas/preview render, not a bug. Instrumenting with a temp log confirmed the runtime value was already correct (onLight:true → black).
**How to apply:** Before changing luminance/logo logic, reproduce against the live runtime value (temp log), not a screenshot. Don't "fix" what is a caching artifact.

## WebDevelopment screens — flat always-visible grid (the 3D deck is GONE)
The web-dev homepage section (`components/WebDevelopment.tsx`) shows the four client website screenshots as a **flat, always-visible grid** (`sm:grid-cols-2`) of browser-chrome cards, each capped `max-h-[360px] object-cover object-top` with a figcaption (client name + category). Layout is a 12-col split: copy `lg:col-span-4` (border-r), screenshot grid `lg:col-span-8`. Animation is one-shot `whileInView` fade/translate + a CSS `group-hover:-translate-y-1.5` lift only.
- **Why the old 3D stacked/hover-expand deck was removed:** the previous version was a tight `preserve-3d` stacked card deck (perspective + rotateX/rotateY/rotateZ, max-w 260–340px) that only fanned out on hover (or `whileInView` on touch). On the user's scaled canvas iframe, hover doesn't trigger, so users only ever saw a tiny skewed stack — reported as "too strange, pages too small, unclear what happens." The flat grid fixes this. There is **no longer any preserve-3d / perspective / hover-to-reveal** here, so don't reintroduce it and don't expect the old `stacked`/`expanded`/`cardVariants`/`canHover` state.

## Long-form "Our Approach" page weaves the whole company deck
`pages/Approach.tsx` (route `/approach`, reached via a CTA button in `components/Methodology.tsx`) is the single page expressing the full studio philosophy sourced from the 74-page deck (`attached_assets/EVILCREATIVES__CA_-_Int_*.pdf`, text dumped to `/tmp/ec_pdf.txt` via `pdftotext -layout` — poppler tools handle the 100MB file fine; the 50MB cap is read-tool-only).

- It mirrors the detail-page scaffold (sticky header, `${import.meta.env.BASE_URL}` for assets, `border-t/b border-white/8` section dividers, framer `whileInView`, data-testid). Sections alternate dark `bg-background` / light `bg-[#f2f0eb] text-[#0d0d0d]`.
- Multi-col grids use the **gap-px + parent divider-bg** pattern (`grid gap-px bg-white/10` dark or `bg-[#0d0d0d]/12` light, children get the section bg) instead of nth-child border utilities — cleaner dividers, no nth-child border bugs.
- **Anton headlines wrap unpredictably:** a long highlighted phrase under tight `leading` (≤0.88) visually overlaps the line above. Use explicit `<br/>` per line + `leading-[0.92]` and a moderate clamp (~`6vw`/`6rem` max), not one `<br/>` with auto-wrap.
- The page is intentionally a lean philosophy/POV page, NOT a services/portfolio page. The Transform-vs-Diffusion comparison, the "Welcome To Our World" services grid, the "Selected Work" named-work list, and the detailed generative-workflow mechanics (pipeline stages + ControlNet toolkit) were all deliberately removed by the user. Don't reintroduce them as "missing content." Current flow (6 sections, strict bright→dark alternation, STARTS bright / ENDS dark): 1 Manifesto hero (bright) → 2 New Canvas (dark) → 3 Market POV (bright) → 4 EVIL AI / Emotional Craft × AI Superpower benefits (dark) → 5 Hacking The Chaos With Clarity (bright) → 6 closing quote (dark). Don't break the alternation when editing.
- Three feature images live in sections 2/3/4 (`approach-cyber.png` cyborg figure, `approach-lipstick.png` lipstick-city, `approach-heart.png` mechanical heart), each in a `lg:col-span-5` right column with framer `whileInView`; the two on dark sections sit over a gold radial-gradient glow. The lipstick image is `aspect-[4/5]` with a dual-gradient CSS mask (both `mask-image`+`mask-composite:intersect` AND `-webkit-mask-image`+`-webkit-mask-composite:source-in`) so its top/bottom/right edges melt into the cream bg — no border.
- Animated background FX + parallax come from reusable `components/BackgroundFX.tsx` (`GridFX`, `Parallax`, `useParallax`). Layering convention: every section is `relative` (add `overflow-hidden` EXCEPT where it would clip 3D/preserve-3d content like WebDevelopment's card deck), `GridFX` renders `absolute inset-0 z-0` (drifting grid for dark / dots for bright sections, plus blurred gold glows), and ALL real content (including the `Bar` component) must be `relative z-10` or it paints UNDER the FX layer. Both components honor `useReducedMotion` (static fallback).
- **GridFX self-clips its glows:** its own root div is `overflow-hidden absolute inset-0`, so the negative-offset gold glow blobs are clipped to the section bounds regardless of whether the SECTION has `overflow-hidden`. So a section can safely be `overflow-visible` (for a 3D deck) without FX bleeding past it. GridFX also has `useInView` gating (margin ~120px; glows only mount while active) so offscreen sections don't run infinite animations — this is what makes it safe to drop GridFX into every section site-wide.
- This FX+parallax treatment is applied SITE-WIDE: all 9 homepage sections, both detail pages, and Approach. Not just Approach.
- **Both detail pages (`AppDevelopmentDetail`, `WebDevelopmentDetail`) use the SAME strict bright/dark alternation as Approach** (cream `bg-[#f2f0eb] text-[#0d0d0d]` + `GridFX light pattern="dots"` for bright; `bg-background` + `GridFX pattern="grid"` for dark). Both START dark (cinematic Anton hero) and the closing section stays dark into the dark Footer (two-dark-adjacent at the footer boundary is intentional/accepted, same as Approach §6→Footer). AppDev order: Hero D → Methodology B → Products D → Capability B → Tagline D. WebDev order: Hero D → Pillars B → Projects D → Footnote B. On bright sections flip every `border-white/8`→`border-[#0d0d0d]/12`, `text-white/40|55|60`→`text-[#0d0d0d]/50|65`, and wrap all content in `relative z-10`. The AppDev hero previously had a `feature-app.mp4` background video — REMOVED per user (replaced with a gold radial-gradient glow + GridFX grid); the mp4 is still used on the homepage `AppDevelopment` component, so keep the asset.
- **DO NOT apply scroll-driven parallax (`useParallax`/`useScroll` translateY) to CONTENT media (product/client screenshots, hero/feature videos) inside `overflow-hidden` frames.** It makes those images/videos VANISH in the user's canvas-iframe preview while staying fine in a direct browser and in full-height agent screenshots. **Why:** the canvas embeds the dev server in a CSS-`transform: scale()`-ed iframe; that scaling corrupts framer-motion's `useScroll` offset math, so `scrollYProgress` blows far outside [0,1], and `useTransform` extrapolates (no clamp by default) into huge `y` values that shove the media entirely out of its clipped frame. Text (no transform) stays visible, so only the images "disappear" — which is exactly the symptom users report. A full-height agent screenshot renders everything in view at mount (scrollY≈0) so it shows the images = FALSE NEGATIVE; reproduce in the real scrolling canvas, not a tall screenshot. **How to apply:** content screenshots/videos are now plain `<img>`/`<video>` (no `useParallax`) on AppDevelopmentDetail (ProductShot + hero video), WebDevelopmentDetail (Screenshot), and the AppDevelopment homepage feature video. Keep them static. `useTransform` in `BackgroundFX` (`Parallax` + `useParallax`) now uses `{ clamp: true }` so any REMAINING decorative `<Parallax>` text wrappers (Approach/Hero/Contact) can never push content more than ±range px even if the scroll math breaks.
- **The framer `useScroll` "Please ensure the container has a non-static position" warning is NOT benign — it co-occurs with the off-screen-media bug above.** An earlier note here wrongly called it a harmless false-positive; that was disproven. When it fires, treat scroll-driven transforms on clipped media as broken in the canvas and remove them (or rely on the clamp). Removing the parallax on the content media made the warning disappear from those pages' console.

## Import images via public/images + BASE_URL, NOT the @assets alias
The evil-creatives vite config DOES define an `@assets` alias (→ `attached_assets/`), but `tsconfig.json` only maps `@/*`, so `import x from "@assets/..."` fails `tsc` typecheck. The whole artifact references images as `${import.meta.env.BASE_URL}images/<name>.png` from `public/images/`.

**Why:** No png module declaration + no `@assets` tsconfig path → typecheck breaks even though Vite would bundle it.
**How to apply:** To use an attached image, copy it into `public/images/` and reference it via `${import.meta.env.BASE_URL}images/...`. Don't add `@assets` imports here.

## The 4 web-* screenshots are dual-use — keep them ~2000px wide
`public/images/web-{ccexplorations,coppernano,quicktime,encore}.png` are used in TWO places: the flat 2-col grid in WebDevelopment.tsx (capped `max-h-[360px] object-cover object-top`) AND full-width (`w-full`) in `pages/WebDevelopmentDetail.tsx`.

**Why:** The detail page renders them near full viewport width (~1800px on wide screens), so downsizing below ~2000w makes that page look soft. Originals were ~2400-2700w/3-5MB. ~2000w is the safe floor (sharp on detail page, still ~half the weight to reduce fan pop-in).
**How to apply:** If optimizing these images, don't go below 2000w, or add srcset. Originals are recoverable from git history via `git show HEAD:<path>`.

## Social share preview: absolute og:image URLs are injected at build time
OG/Twitter share-image URLs MUST be absolute (Slack/X/iMessage/LinkedIn crawlers silently ignore relative og:image/og:url). `index.html` uses `%OG_SITE_URL%`/`%OG_IMAGE_URL%` tokens that a Vite `transformIndexHtml` plugin replaces from `REPLIT_DOMAINS` + `BASE_PATH` — do NOT hardcode the domain.

**Why:** A hardcoded dev-domain string breaks previews on a custom/production domain; deriving from `REPLIT_DOMAINS` keeps them valid across deploys.
**How to apply:** To regenerate the branded card, rasterize an SVG with ImageMagick (`sharp` is NOT installed here) and force exactly 1200x630 (`-resize 1200x630^ -gravity center -extent 1200x630`); keep the meta width/height in sync with the actual file.

## Prod publish bundles ALL artifacts — a failed api-server healthcheck rolls back the whole site
The project deploys every artifact together. If `artifacts/api-server`'s startup healthcheck (`/api/healthz`) fails during publish, the entire deployment is rejected and the live site stays on the PREVIOUS successful version.

**Why:** User reported images/hero video "disappeared" on /app-development and /web-development in production while dev rendered everything fine. Root cause was NOT code: dev preview, the evil-creatives prod build (all assets land in dist/public), and the api-server prod bundle (`/api/healthz` → 200) were all verified healthy. Two prior publishes had failed the api healthcheck (transient/cold-start 500s), so prod was stuck on an old commit that predated the newer detail-page images.
**How to apply:** When prod looks stale/missing-assets but dev is correct, check `fetch_deployment_logs` for healthcheck failures before touching code. The fix is usually just to re-publish; only debug the api-server if healthz genuinely 500s when running the prod bundle locally (`PORT=xxxx NODE_ENV=production node artifacts/api-server/dist/index.mjs`).
